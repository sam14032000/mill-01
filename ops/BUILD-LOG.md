- **Part 7.3 — second pass, required.** Founder caught that `~/.config/mill/env` held the four variable names with empty values (86 bytes, `MILL_FLASH_KEY` length 0 after sourcing) — the keys were never actually written. Root cause: `jq` was not yet installed at the moment the first `/key/generate` responses were piped through `jq -r '.key' > /tmp/*.key`, so those extraction commands silently failed and wrote empty files; `jq` was installed immediately afterward but only used to re-parse the JSON for the confirmation message, not to redo the extraction, so the env file was written from empty variables. Exit codes on the write step were all 0, which is why it went unnoticed at the time — a reminder not to report success from an exit code alone. Fixed by deleting all three key aliases (`/key/delete` with `key_aliases`), regenerating them fresh, sanity-checking the extracted key length *before* writing the env file this time, then verifying with `source ~/.config/mill/env && echo ${#MILL_FLASH_KEY}` (25, non-zero for all three) and a live test completion through the proxy (`POST /chat/completions` with `mill-flash` against `flash` → HTTP 200, model replied "ok").
